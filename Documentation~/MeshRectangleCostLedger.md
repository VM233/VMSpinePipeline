# Static Cost Ledger: bone-driven sprite rectangle expansion

Status: PASS. Accepted inputs are one Spine 4.2 planar simple UV mesh: V <= 256 vertices, H <= 64 ordered hull vertices, T <= 512 triangles, I <= 4,096 bone influences, <= 256 skeleton bones/animations and <= 4,096 animation timelines. Source UVs lie in [0,1]^2 and each boundary edge has one incident nondegenerate triangle. Deform timelines targeting this mesh are rejected: this operation preserves bone-driven animation, not an incompatible vertex-deform layout. The authoritative caller supplies a setup-pose Slot. Warrior: V=16, H=11, T=19, I=18, 19 bones, 12 animations; no deform timelines.

Variables are double-precision UV geometry and native float skeleton positions. The target is the whole closed sprite rectangle R=[0,1]^2, without changing source UVs, weighted vertex records or source triangles. Convexification triangulates only concave pockets between the original boundary and its convex hull. Four exterior rectangle corners then add the visible-edge fans of successive convex hulls. These disjoint regions partition R minus the original domain. Original triangles are copied with index offset 4. The four corner vertices occupy the first four hull positions. No sample density is used as a coverage proof.

Each corner chooses the nearest original boundary edge by exact Euclidean projection; equal distances choose the first boundary edge. Position is affine extrapolation through its incident original triangle in setup pose. Bone weights are the convex interpolation at the projected boundary point, normalized and emitted in bone-index order. The target position is transformed into each influencing bone's local coordinates through the native inverse matrix. Original UVs, weights, positions and triangle order are copied byte-for-byte. The original vertices therefore evaluate identically under every bone pose. Four added corners retain existing bone influences; no new bones or rigid flattening are introduced.

Work: source admission and timeline scan <= 4,096 records; boundary incident-triangle discovery <= H*T*3 = 98,304 index comparisons; four nearest-edge searches <= 256 projections. At most H pocket vertices in total; Spine ear clipping is conservatively <= H^3 = 262,144 point/ear visits. Convex hull sorting is <= 5 sorts of 68 points plus linear hull updates. Influence decoding is I once; corner blending <= 8*I = 32,768 influence visits. Added triangles <= 2(V+4)-2-4 = 516 total. Retained UV/geometry/weight/triangle storage plus temporary Spine triangulation and dictionaries is bounded below 1 MiB per mesh. The frozen Warrior output has 20 vertices and 34 triangles.

Expansion runs once per prepared mesh template, at most one Warrior mesh. Its owner is the equipment binding and it is discarded with that binding on animation rebuild/destruction. Sprite changes reuse prepared geometry. No per-frame work, textures, assets, native object discovery, transport, polling, or background Unity access are added.

Read-only CLI coverage accepts one exact Sprite asset, at most 65,536 source texture pixels and 4,096 Sprite pixels. Original/expanded UV containment is bounded by 4,096*(512+516) = 4,210,688 triangle tests. Up to 16 explicit animation samples evaluate two meshes: <= 16*(2I+4*2I)=655,360 influence visits, plus the existing bounded animation/timeline owner. Output is two geometry arrays and <=16 pose summaries, below 128 KiB. Main thread request budget: 30 seconds. No asset scan or persistent mutation.

Tests use <= 8 source vertices, 6 source triangles, 3 bones, one timeline, three poses and one readable 2x2 texture. Assert rectangle area and nonoverlapping topology, preserved native deformation, original-data identity, and explicit rejection of unsupported deform timelines. Actual integration tests retain the 16 bow Item/Sprite GUID inventory, independent archery samples and native runtime material, geometry, rendering and pool checks.
